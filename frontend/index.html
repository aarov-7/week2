Explain the difference between SAML and OAuth. When would a company choose on over the other?

SAML is about authenticating the user and OAuth is about authorizing users and applications. A company would pick SAML when it wants to enterprise SSO of workforce access to SaaS tools or if their existing infrastructure already speaks SAML. A company would pick OAuth when working with mobile apps or when allowing users to log in using other services, for example google or apple.

What is a Web Application Firewall (WAF) and what kinds of attacks does it defend against? Where would you place one in the three-container architecture you built in Week 4 (Route -> frontend -> backend -> db)?

A web application firewall is a security layer that inspects HTTPS traffic at the application layer and blocks suspicious requests. WAF can defend against SQL injections, command injections, app layer denial of service attacks and bot traffic among others. I would put WAF in between the route and frontend in my week 4 project.

Explain what a peer-to-peer VPN (for example n2n) is used for, and how it differs from a traditional site-to-site VPN

A peer to peer vpn connects the individual devices together rather than connecting through a central vpn gateway. Computers on p2p vpns behave as if they were on the same lan network. It differs from a traditional site to site vpn via having the users connect directly to one another instead of connecting through a vpn gateway.

What is YAML and why has it become the default configuration format for kubernetes/rahti manifests? Compare it briefly to JSON.

YAML is a human readable data serialization format. It represents the same kind of data as JSON but is simpler to read. It became the default for kubernetes/rahti due to it's readability, ability to leave comments and support for multiple resources per file. YAML uses indentation such as dashes, JSON uses braces and brackets. YAML has comments, JSON doesn't. YAML is more complex and thus slower and less reliable than JSON.
